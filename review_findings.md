# Review findings (verified, pending entry into development.md)

## Known bugs

- **One IPython line anywhere breaks manifest extraction for the whole notebook.** `generate.extract_manifest_from_file` joins every code cell into one source and calls `ast.parse` once, after blanking lines that start with `%` or `!`. A single `files = !ls`, `x = %timeit ...` or `df?` survives the blanking and fails the parse, so the notebook returns "Could not parse" and check and delta break (confirmed with a two-cell notebook). The blanking itself also turns valid Python invalid: a triple-quoted string whose closing line starts with `%`, a backslash continuation line starting with `% `, and a parenthesized condition whose last line starts with `!= b)` all parse before stripping and fail after (tested). Fix: parse per cell (the manifest lives in one cell), and replace the blanking with one shared helper.
- **A scan silently loses every import in a cell it can't parse.** `scanning.py` applies the same line-blanking (copy-pasted twice, a third copy is in `generate.py`) and, on `SyntaxError`, drops the cell with no diagnostic. A notebook with one magic in expression position loses that cell's imports while the report looks complete. This is false success; at minimum emit a diagnostic naming the cell.
- **A dropped connection during a PyPI fetch crashes the run.** `pypi._fetch_pypi_json` reads the response inside the try, but catches only `HTTPError`, `URLError`, `TimeoutError` and `JSONDecodeError`. Errors raised during the read (`http.client.RemoteDisconnected`, `IncompleteRead`, SSL errors) escape, so one transient drop exits 2 instead of reporting `NETWORK_ERROR`. Fix: catch `OSError` (which already covers `URLError` and `TimeoutError`) and `http.client.HTTPException`.
- **Local-module detection depends on an incidental import.** `localmodules._found_in_dir` calls `importlib.machinery.PathFinder`, but the module imports only `importlib.util`, which does not bind `importlib.machinery` (AttributeError in a clean 3.12 interpreter). It works today only because `installed.py` imports `importlib.metadata`. If that changes, the `except Exception` swallows the error and every local module silently reports as not found. Fix: `import importlib.machinery`.
- **Transitive checks evaluate platform markers against the machine running check.** `drift._marker_environment` overrides only the Python version and extra and takes the rest from `default_environment()`. Running check on Windows against a Kaggle or Colab notebook drops Linux-only requirements (torch's `nvidia-*` dependencies are marked `platform_system == "Linux"`) and includes Windows-only ones. Fix: set `sys_platform`, `platform_system`, `os_name` and `platform_machine` from the target when it is Kaggle or Colab; keep the host values for a local target.
- **OpenCV variant detection has its own view of what's installed.** `resolution.resolve_opencv_variant` runs `pip list` in a subprocess on every call, unmemoized, even though the caller already holds `frozen_env` from the run's single `pip freeze`. Two independent sources of installed state can disagree. Fix: derive the variant from `frozen_env`.
- **Replacing a prior setup cell can discard user code.** `generate.is_prior_setup_cell` matches any code cell that assigns `STEADY_PY_MANIFEST` anywhere, including inside a function (`ast.walk`), and `write_locked_notebook` drops the whole cell with no warning. With `--in-place` a user's scratch cell that copied the assignment is lost from the original. The content match is deliberate (untagged pasted cells must be replaced), so the fix is a warning when a removed untagged cell contains other statements, not dropping the match.
- **A package that can't be looked up becomes a confirmed conflict.** `drift.resolve_transitive_graph` excludes root pins not found on PyPI, but `_PyPIResolutionProvider.find_matches` returns no candidates for any transitive package whose fetch status isn't FOUND. Resolvelib then raises `ResolutionImpossible`, reported as a CONFIRMED conflict. Triggers: a transitive dependency hosted only on a custom index (NVIDIA's index packages), or, more likely, a transient network error on any transitive fetch. "Could not look it up" should be reported as unverifiable.
- **Extras promotion is nondeterministic and records at most one extra.** `resolution.resolve_pypi_package_and_extras` iterates the submodule `set` and stops at the first tail name that matches a `Provides-Extra`, so with two matches the chosen extra depends on hash randomization and can differ between runs. Name matching also misses most extras, since extras rarely share names with submodules, and pip does not record which extras were requested at install time. A sounder heuristic: an extra counts as installed if its `Requires-Dist` entries are all present.
- **Display text is parsed back as data.** `analyze.analyze_batch_repository` recovers a package name from `dep.comment_text.split()[1]` when `dep.name` is empty, and `generate.py` filters auxiliary entries with `aux.comment_text.startswith("\n# ---")`. Both are strings the tool built earlier in the same run, so they can't be tampered with, but rewording a comment would silently misfile packages. Carry structured fields (name, status) instead of parsing rendered text.
- **The setup markdown cell is recognized by its heading text.** `generate.is_prior_setup_cell` falls back to matching `SETUP_MARKDOWN_HEADING`, which is unprotected notebook text. If a user edits the heading and the cell has lost its managed tag, the old setup cell survives as a stale duplicate. Low severity: the managed tag is the primary signal.


### Guards and install harvesting

- **A guarded install line erases every import in its cell.** In a cell containing `import pandas` and `if IN_COLAB:` followed by an indented `%pip install xyz`, the line blanking leaves an empty if-body, `ast.parse` raises `SyntaxError`, and the scan returns zero imports for the cell with no diagnostic (confirmed by running `scanning.extract_import_occurrences_from_source` and `extract_imports_from_sources_full`). The standard guarded-install pattern silently removes real dependencies.
- **A guarded import loses its guard when the pip name differs.** `resolution.build_unified_timeline` computes `is_guarded = pkg_name in guarded_set`, where `pkg_name` is the install line's pip name (`python-dotenv`, `scikit-learn`) and `guarded_set` holds import names (`dotenv`, `sklearn`). The lookup never matches, so the package is installed although its import is guarded (verified by running). The same key mismatch drops submodules (`submodules_map` is keyed by import name), so extras promotion never fires for such packages.
- **A guarded install line is installed unconditionally.** `magics.harvest_pip_install_occurrences` matches lines with a regex and has no scope information, so `if IN_COLAB: %pip install x` is treated as a top-level install (verified by running). Raw installs and index URL flags are harvested the same way, regardless of guard (read from code).
- **A variable install becomes a package named `$pkg`.** `%pip install $pkg` is harvested literally (verified by running). A static scan cannot know the value; this should be a warning, not a package.
- **Several install forms are not detected, and nothing warns.** `!python -m pip install`, `!{sys.executable} -m pip install`, `os.system(...)`, `subprocess` calls and `get_ipython().system(...)` are all missed (verified by running). `PIP_INSTALL_PATTERN` recognizes only `%pip`, `!pip` and bare `pip`/`pip3`.
- **Mutually exclusive branches collapse to the last pin.** `magics.resolve_pip_occurrences` is last-wins by canonical name, which is correct for sequential reinstalls but wrong when two branches install the same package with different pins or flags; only a warning remains (read from code).
- **Non-literal dynamic imports get a generic warning with no guard state.** Only `importlib.import_module` (including aliased bindings) and `__import__` are recognized (read from code).
- **Guard tagging is coarse.** `TYPE_CHECKING`, `if __name__ == "__main__"` and platform flags are treated like `try/except ImportError`, and alternatives have no group identity or intent class (read from code).
- **A wrapper helper that shells out to pip loses the guard at its call site** (read from code).
- **A second, test-only resolution path carries its own guard logic.** `resolution.build_manifest_entries`, `build_dependency_objects` and `process_package_requirements` are called only from tests, and duplicate the guard and resolution logic of `build_unified_timeline`. Tests pass against code production never runs. Remove them or move their tests onto the live path.
- **`--opt=value` pip flags are silently dropped.** `magics.harvest_pip_install_occurrences` splits arguments on spaces and matches index flags exactly, so `--index-url=https://...` and `--extra-index-url=...` fail the match and are then skipped as generic flags. Both it and `harvest_index_urls_from_sources` return no URL (confirmed); the space-separated form works. Cell 2 then searches public PyPI and fails.
- **PEP 508 direct references are split into three entries.** `%pip install "pkg @ git+https://..."`, the form pip accepts, yields packages `pkg` and `@` plus a detached raw install of the URL, because `split()` runs before quotes are handled (confirmed). The unquoted form is a pip error and should be flagged, not registered.
- **`%%writefile` cells with leading blank lines are scanned as notebook code.** `scanning.classify_cell_source` checks only the first line, so a blank first line makes the cell PYTHON and its imports (`import torch` in the test) become notebook dependencies (confirmed). IPython's `TransformerManager` strips leading blank lines and runs the cell as `run_cell_magic('writefile', ...)`, so IPython accepts this form.

### Cell 2 runtime (`runtime.install`)

- **Pins with extras never pass the already-installed check.** A promoted name such as `packaging[foo]` is written to the manifest as-is, and `importlib.metadata.version("packaging[foo]")` raises `PackageNotFoundError` (confirmed). The `except Exception: pass` hides it, so pip reruns on every execution, `any_install_performed` fires the restart warning, and the package never enters the drift baseline. Stripping the brackets is not enough: the base package being present doesn't mean the extra's dependencies are. Either check the extra's `Requires-Dist` entries or let pip handle bracketed names (pip is idempotent and correct for extras).
- **A pin that drifts after being verified still counts as verified.** If package A passes and a later install changes its version, the loop prints a drift line, but `passed_count` still includes A and the summary reads "Setup complete! All N/N dependencies verified." This is false success. Packages outside the manifest (for example, a platform package an install downgrades) aren't tracked at all, because the baseline holds only manifest packages already visited. Fix: snapshot `importlib.metadata.distributions()` before and after the loop, report the diff, and re-verify every manifest pin before printing the success line.

## Design gaps

- Optional dependencies that are never imported (openpyxl, gcsfs, spaCy models) are seen only if the notebook has an install line. There is no candidate detection. Package metadata can supply candidates without a hardcoded list: pandas declares openpyxl and gcsfs in its extras, so an imported package plus an installed package named in one of its extras is a candidate. spaCy models are declared in no metadata and need a different signal.
- There is no creator warning about guarded alternatives, and no runtime report of which alternatives are present. A clean run cannot verify the untaken branch.
- It is unknown whether a platform baseline (Kaggle or Colab preinstalled packages) exists; candidate lists need one.
- Guard, unresolved and install-only status exist only as Cell 2 comments; the manifest has no protected record of them. `check` and the planned report of which guarded alternatives are present need them as manifest fields.


## Principles

- Cell 2 is never hand-edited. Creator declarations are inputs to the tool.
- Report to the creator is the default for candidates and unknown targets. Never auto-add.
- Hard dependencies are out of scope. Optional dependencies are in scope.
- Comments and other display text are never a source of truth. Anything the tool needs later is a structured, hashed manifest field; anything it needs within a run is carried as a typed field, not parsed back out of rendered text.


## Proposed fixes

- **Parse magics into Python, then scan one AST.** Transform `%` and `!` lines, `x = !cmd` and `obj?` into `get_ipython()` calls before parsing. IPython's `TransformerManager` (`IPython.core.inputtransformer2`) does this; IPython is not a base dependency, so use it when importable and fall back to a small transformer of our own. Install commands then inherit the guard state of their enclosing block. Also fixes the stripping bugs above and replaces the three copies of the blanking code.
- **Join pip names to import names through installed metadata.** Use the run's `packages_distributions()` (`pkg_dist_map`) first and `IMPORT_TO_PYPI_MAP` as a fallback, so guards and submodules carry across name differences. Decide which wins when an unconditional install meets a guarded import (the defect above implies the guard does).
- **Harvest literal shell-outs; warn on the rest.** After the AST change, `os.system`, `subprocess` and `get_ipython().system` calls with literal pip arguments are recordable with their guard state. Emit a `DiagnosticEvent` only for non-literal arguments, including `%pip install $pkg` and non-literal dynamic imports.
- **Parse pip arguments the way pip does.** Tokenize with `shlex.split`, use an option table that accepts both `--opt value` and `--opt=value`, and parse requirement tokens with `packaging.requirements.Requirement` (already a base dependency). The magics-to-AST change doesn't cover this, since `run_line_magic` still receives the raw argument string.
- **Deferred: keep alternative pins per branch.** Cell 2 installs one environment, so keeping both pins needs a way to say which branch applies at runtime. Depends on guard identity and creator declarations; until then, report to the creator.

## Reviewed and rejected

- `_RUN_CACHES` as a memory leak or thread hazard: caches are created once at import (four decorated functions) and nothing in the tool runs concurrently.
- `silence_fd2_stderr` swallowing other threads' output: intentional, and scoped to the brief CUDA probe window.
- Replacing `pip freeze` with `importlib.metadata`: it runs once per run, so the speedup is small, and re-implementing freeze semantics (editables, direct references, name forms) adds drift risk.
- Optional-dependency detection as a rabbit hole requiring a hardcoded knowledge base: the objection targets auto-adding, which the principles already exclude, and extras metadata supplies candidates without a hardcoded list.
